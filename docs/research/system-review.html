รีวิวทั้งระบบ · หน้าไหนยังไม่ได้ดู และควรปรับอะไร

25 ต.ค. 69 · นับจากหน้าในระบบทั้งหมด 66 หน้า (ไม่รวมหน้าที่แค่ส่งต่อไปหน้าอื่น) · เปิดดูหน้าจริงบนเครื่อง dev · ยังไม่ได้แก้อะไร

1. หน้าที่รีวิวแล้ว

แดชบอร์ดยอดขายปิดร้านประจำวัน (ใหม่) จัดการเมนูทดลองเมนู สินค้า/วัตถุดิบ (รายการ + แผง)งานสต๊อก · ปรับ · ประวัติ/บัตรสต๊อก นับสต๊อก (รายการ)ของเสียโอนของ (รายการ)มื้อพนักงาน ใบสั่งซื้อ (รายการ + ฟอร์ม)รับสินค้า (รายการ + ฟอร์ม)ซัพพลายเออร์ + สั่งของ ต้นทุนต้นทุนตามแผนกของหายไปไหนการผันผวนราคา วิเคราะห์รายจ่ายหมวดบัญชี (กล่องตามกลุ่ม) ค่าใช้จ่าย (รายการ — แค่คลิกทั้งแถว)ค่าใช้จ่ายประจำ (แค่คลิกทั้งแถว)ตัดสต๊อกตามยอดขาย (แค่แก้ข้อความ)

2. หน้าที่ยังไม่ได้รีวิว — เรียงตามความถี่ที่ร้านใช้

P1 = ใช้ทุกวัน/ทุกสัปดาห์ หรือมีปัญหาที่เห็นชัด · P2 = ใช้เป็นช่วง ๆ · P3 = ตั้งค่าครั้งเดียว · ตัวแดง = สิ่งที่เจอบนหน้าจริงวันนี้

หน้าใช้ทำอะไรที่เจอ / ที่ควรเป็น (best practice)
นำเข้ายอดขาย
/sales/import		อัปโหลดไฟล์ POS ทุกวัน/ทุกสัปดาห์ปุ่มเลือกไฟล์ของเบราว์เซอร์เป็นภาษาอังกฤษ "Choose File · No file chosen" · ประวัติขึ้น "0 รายการ" ทั้งที่ไฟล์มีทั้งเดือน · มาตรฐานการนำเข้าไฟล์: ลากวางได้ · 4 ขั้น เลือกไฟล์ → จับคู่คอลัมน์ → ตรวจ → ยืนยัน · บอกสรุปก่อนกดยืนยัน ("26 วัน 1,695 แถว ยอดขาย ฿615,380") · แสดงแถวที่ผิดพร้อมเลขแถวให้แก้P1
ตัดสต๊อกตามยอดขาย
/consumption		ตัดใหม่หลังแก้สูตรไม่มีหัวข้อหน้า · ทุกแถวเขียน "ดู 3 เมนูที่ตัดไม่ได้" ซ้ำกัน 32 แถว (เป็นเมนูชุดเดิม) · ปุ่ม "ตัดสต๊อกตามสูตร 32 วัน" ไม่บอกว่าจะเกิดอะไร · ช่องเลือกสาขา + ปุ่ม "ดู" แบบเก่า · ควร: บอกครั้งเดียวด้านบนว่า "3 เมนูไม่มีสูตร → เขียนสูตร" · แยก "วันที่ต้องตัดใหม่" ไว้บนสุด · ชิปสาขาเหมือนหน้าอื่นP1
บันทึก/ดู/แก้ค่าใช้จ่าย
/expenses/new · [id] · edit · รายการ		ลงบิลค่าใช้จ่ายทุกวันหมวดบัญชีและผู้ขายเป็น dropdown ยาว · วิธีชำระเงินพิมพ์เอง (เงินสด/โอน/บัตร ควรเป็นปุ่มเลือก) · ฟอร์มยาวหลายช่องที่ไม่ค่อยใช้ (เลขใบกำกับภาษี) โชว์ตลอด · มาตรฐานแอปบันทึกค่าใช้จ่าย: ใช้บนมือถือได้เร็ว · ถ่ายรูปบิลแล้วค่อยกรอก (รอที่เก็บไฟล์) · จำหมวด/ผู้ขายล่าสุด · ช่องขั้นสูงพับไว้P1
ค่าใช้จ่ายประจำ
/expenses/recurring + new/edit		ค่าเช่า เงินเดือน ฯลฯตอนนี้แดชบอร์ดเตือนว่าค่าใช้จ่ายประจำยังไม่ลง → หน้านี้ควรมีปุ่ม "ลงของเดือนนี้" ทีละรายการ/ทั้งหมด และบอกว่ารายการไหนถึงกำหนดแล้วP1
นับสต๊อก — แผ่นนับ
/stock-counts/[id]		นับจริงหน้าตู้ บนมือถือรายการรีวิวแล้วแต่แผ่นนับยังไม่ได้ดูเต็ม · มาตรฐาน: ใช้มือเดียวบนมือถือ · เรียงตามจุดเก็บของ (ตู้แช่/ชั้นแห้ง) · ปุ่มใหญ่ · เห็นว่านับไปกี่จากกี่รายการ · ทำงานต่อได้เมื่อเน็ตหลุดP1
ใบขอซื้อ + ตัดรอบ
/purchase-requests · /cut		ครัวขอของ จัดซื้อตัดรอบสร้างใน Part 38 หน้าตาเรียบร้อย แต่ยังไม่ผ่านรอบรีวิว · มาตรฐานใบขอซื้อร้านอาหาร (Supy, Odoo): เติมจำนวนแนะนำจากขั้นต่ำ · กดอนุมัติ/ปฏิเสธได้จากมือถือ · แจ้งเตือนเมื่อสถานะเปลี่ยนP2
หน้าเอกสารรายใบ
ใบสั่งซื้อ · ใบรับของ · ใบโอน · [id]		เปิดดูจากลิงก์/บัตรสต๊อกเพิ่งเริ่มมีลิงก์เข้าจากบัตรสต๊อก · ควรมีหัวเหมือนกันทุกใบ (เลขที่ สถานะ ใครทำ เมื่อไหร่) · ปุ่มงานถัดไปเด่น (รับของ/ยืนยัน/ยกเลิก) · ลิงก์ไปเอกสารที่เกี่ยวกัน (PO ↔ ใบรับ ↔ ค่าใช้จ่าย)P2
ต้นทุนรายวัตถุดิบ / ตารางละเอียด
/cost/[productId] · /cost/detail		เจาะลึกจากหน้าต้นทุนหน้าแบบเก่า (ก่อนรีวิวต้นทุน) · /cost/[productId] ซ้ำกับแผงสินค้า + บัตรสต๊อกที่เพิ่งทำ → พิจารณาให้ลิงก์ไปบัตรสต๊อกแทน (ตัดหน้าซ้ำ ตามหลักที่คุณ Kong วางไว้)P2
ตั้งค่าร้าน
/settings		ตั้งครั้งเดียว ปรับนาน ๆ ครั้งหน้ายาวหน้าเดียวรวมทุกอย่าง · โหลด ~6 วินาที · ปุ่มบันทึกอยู่ล่างสุด บางส่วนบันทึกทันที (ปิดร้าน) บางส่วนต้องกด → สับสน · มาตรฐานหน้าตั้งค่า SaaS: แบ่งหมวด (ร้าน · ภาษี · การคำนวณ · สต๊อก · add-on) มีเมนูข้าง · บันทึกแบบเดียวกันทั้งหน้าP2
คนในร้าน

3. ฟีเจอร์/งานข้ามหน้าที่ยังไม่ได้ปรับ

  • การเริ่มใช้ครั้งแรก (onboarding): ร้านใหม่เปิดมาเจอหน้าว่าง ไม่มีรายการ "ทำ 5 อย่างนี้แล้วเริ่มใช้ได้" (เพิ่มวัตถุดิบ → ซัพพลายเออร์ → นำเข้ายอดขาย → เขียนสูตร → นับสต๊อกครั้งแรก) — แนวปฏิบัติ B2B: 3–7 ขั้น มีแถบความคืบหน้า และหน้าว่างแต่ละหน้าบอกปุ่มเดียวที่ต้องกด
  • มือถือ: ยังไม่เคยไล่ทุกหน้าที่ความกว้างมือถือ — หน้าที่ใช้หน้างาน (นับ ของเสีย ปิดร้าน รับของ ขอซื้อ) สำคัญที่สุด
  • รูปถ่าย/ไฟล์แนบ (Tigris): รูปสินค้า · รูปบิลค่าใช้จ่าย · หลักฐานใบโอน · รูปนับเงินปิดร้าน — เลือก vendor แล้ว รอ dependency + .env
  • การอ่านที่ยังเป็น Server Action: 16 จุด (สินค้า ใบสั่งซื้อ ตัดสต๊อก ใบขอซื้อ ต้นทุน มื้อพนักงาน เมนู ทดลองเมนู รวมเมนู สต๊อก รับของ นับสต๊อก) — ทำให้ช้า/ค้างได้ ย้ายเป็น GET ตอนรีวิวแต่ละหน้า
  • ความเร็ว: ตั้งค่าร้าน ~6 วินาที · แนวโน้มรายสัปดาห์ของต้นทุนตามแผนก ~10 วินาที
  • ค้างจากรอบก่อน: สาเหตุการปรับสต๊อกเพิ่ม (คีย์ผิด/เจอของ/ยอดยกมา) · จำนวนลูกค้าจากไฟล์ POS · อีเมลแจ้งจัดซื้อแบบเลือกรายคน · ต้นทุนสาขาอื่นในแผงเมนู · ลองด้วยบัญชีพนักงานครัว/ผู้จัดการในเบราว์เซอร์
  • ฟีเจอร์ใหญ่ที่รอหลังรอบ UI (ตามที่คุณ Kong วางลำดับไว้): ADR 0037 รับของ/เจ้าหนี้ · ADR 0038 สิทธิ์ที่ร้านปรับเอง · ขั้นต่ำแยกแผนก · แพ็กเกจราคา · ตรวจสอบการคำนวณ · AI (สรุป P&L อ่านบิล ร่างสูตร)

4. ลำดับที่เสนอ

  1. นำเข้ายอดขาย + ตั้งรูปแบบไฟล์ — ใช้บ่อยที่สุดในกลุ่มที่เหลือ และมีปัญหาเห็นชัด (ปุ่มภาษาอังกฤษ · "0 รายการ")
  2. ตัดสต๊อกตามยอดขาย — เล็ก แก้เร็ว
  3. ค่าใช้จ่าย (บันทึก · รายใบ · ประจำ) — ใช้ทุกวัน และผูกกับคำเตือนบนแดชบอร์ด
  4. แผ่นนับสต๊อกบนมือถือ
  5. หน้าเอกสารรายใบ (PO · ใบรับ · ใบโอน) ให้หัวเหมือนกัน + ตัด /cost/[productId] ที่ซ้ำกับบัตรสต๊อก
  6. ใบขอซื้อ · ซัพพลายเออร์รายราย
  7. ตั้งค่า · คนในร้าน · สาขา · แผนก (แบ่งหมวด บันทึกแบบเดียวกัน)
  8. เข้าสู่ระบบ/สมัคร + onboarding ครั้งแรก — ควรทำก่อนให้ร้านแรกใช้จริง
  9. รวมเมนู · สูตรของแปรรูป · รายชื่อพนักงาน
  10. ไล่มือถือทั้งระบบเป็นรอบสุดท้าย
