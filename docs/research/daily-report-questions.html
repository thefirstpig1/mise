รายงานประจำวัน · บรีฟก่อนออกแบบ

โจทย์จากคุณ Kong (24 ต.ค. 69 ใต้ข้อ C1): จำนวนลูกค้าต่อวัน · ปัญหาที่เกิด · กลุ่มลูกค้า · รูปถ่ายนับเงินสดเป็นหลักฐาน — ยังไม่มีหน้าจอ ยังไม่แตะโค้ด

1. คำถามที่เจ้าของ/ผู้จัดการถามจากรายงานประจำวัน

รวบจากแบบฟอร์ม manager log และ end-of-day close ที่ร้านอาหารใช้กันจริง (แหล่งท้ายหน้า) แล้วเรียงตามที่คนอ่านถามก่อน

Q1เงินครบไหมควรมีเงินสดเท่าไหร่ นับได้จริงเท่าไหร่ ขาด/เกินกี่บาท ใครนับ — ทุกแบบฟอร์มให้จดยอด "ที่ควรมี" ก่อนนับ เพื่อไม่ให้ย้อนมาเติมทีหลัง และให้จดส่วนต่างเป็นข้อเท็จจริง (จำนวน · ใคร · เวลา)
Q2ลูกค้ากี่คน จ่ายต่อหัวเท่าไหร่จำนวนลูกค้า (covers) · จำนวนบิล · ยอดต่อหัว / ต่อบิล — ระบบใหญ่แยกตามช่วงเวลา (กลางวัน/เย็น) ด้วย
Q3ลูกค้ามาจากไหนนั่งร้าน · กลับบ้าน · Grab · LINE MAN · ShopeeFood … แต่ละกลุ่มกี่คน/กี่บาท
Q4วันนี้มีปัญหาอะไร และใครต้องตามต่อของหมด (86) พร้อมวันที่จะกลับมา · อุปกรณ์เสีย (บอกอาการ ไม่ใช่แค่ "เสีย") · ลูกค้าร้องเรียน · พนักงานขาด/สาย · แยก "ต้องจัดการก่อน" ออกจาก "จดไว้เฉย ๆ" ให้คนเปิดร้านพรุ่งนี้รู้ว่าต้องทำอะไรก่อน
Q5วันนี้ปกติไหมเทียบกับวันเดียวกันของสัปดาห์ก่อน ๆ (วันศุกร์เทียบวันศุกร์) — ตามกฎเดิมของระบบ ทุก % ต้องบอกว่าเทียบกับอะไร
Q6มีหลักฐานไหมรูปเงินที่นับ / ใบนำฝาก / Z report ถ่ายตอนนั้นเลย มีเวลาติด ไม่ใช่ถ่ายย้อนหลัง

2. ระบบมีอะไรอยู่แล้ว ขาดอะไร

ข้อมูลสถานะมาจากไหน / ต้องทำอะไร
ยอดขายของวันมีแล้วไฟล์ POS + ยอดที่คีย์ตอนปิดร้าน (ADR 0020) — ยอดที่คีย์อยู่ที่แดชบอร์ด (B9)
จำนวนบิล · ช่องทางมีที่เก็บ แต่ไม่มีข้อมูลตาราง sales_line เก็บเลขบิลและช่องทาง (9 ช่องทาง รวม Grab/LINE MAN/ShopeeFood) ได้อยู่แล้ว แต่ร้านตัวอย่างนำเข้าไฟล์สรุปรายวัน: 1,695 แถว มีเลขบิล 0 แถว มีช่องทาง 0 แถว
จำนวนลูกค้าไม่มีไฟล์ POS ไม่มี (ร้านส่วนใหญ่ก็ไม่มี) → ต้องให้คนกรอก
เงินสดที่ควรมี / นับได้ไม่มีไฟล์ POS ไม่มีวิธีชำระเงิน จึงคำนวณ "ควรมี" เองไม่ได้ → ให้กรอกยอดเงินสดจาก Z report ของเครื่อง POS + เงินทอนตั้งต้น แล้วระบบลบให้
ปัญหา / ส่งต่อกะไม่มีมีแค่ "หมายเหตุ" ข้างยอดที่คีย์ → ต้องทำเป็นรายการที่มีประเภท และมี "ต้องตามต่อ / จัดการแล้ว"
ของเสีย · มื้อพนักงาน · โอนของ · ของใกล้หมด · ตัดสต๊อกมีแล้วดึงมาโชว์เอง ไม่ต้องกรอกซ้ำ — รายงานจะเป็นที่เดียวที่เห็นวันนั้นครบ
รูปถ่ายยังเก็บไม่ได้ระบบยังไม่มีที่เก็บไฟล์ (เลื่อนไว้รอ object storage ตั้งแต่ตอนวางเรื่องรูปสินค้า) → ต้องเพิ่ม dependency + ตั้งค่า .env = ต้องตัดสินใจก่อน

ข้อสังเกต: ถ้าทำหน้านี้แยกจาก "คีย์ยอดปิดร้าน" จะกลับไปเป็นปัญหาข้อมูลซ้ำที่เพิ่งแก้ใน B9 — ยอดปิดร้านควรเป็น ช่องหนึ่งของรายงานนี้ แล้วแดชบอร์ดมีปุ่ม "ปิดร้านวันนี้" แทน

3. รูปร่างที่เสนอ (ยังไม่ใช่ดีไซน์)

"ปิดร้านประจำวัน" — หนึ่งใบต่อสาขาต่อวัน กรอกตอนปิดร้านบนมือถือ ไม่เกิน 2 นาที

① ยอดยอดที่ลูกค้าจ่ายวันนี้ (ช่องเดิมจากแดชบอร์ด)
② เงินสดเงินสดตาม Z report · เงินทอนตั้งต้น · นับได้ → ขาด/เกิน อัตโนมัติ · รูป
③ ลูกค้าจำนวนลูกค้า (ใส่รวม หรือแยกกลุ่ม)
④ ปัญหาแตะประเภท + พิมพ์สั้น ๆ + ติ๊ก "ต้องตามต่อ"
⑤ ระบบเติมให้ของเสีย · มื้อพนักงาน · ของหมด/ใกล้หมด · ตัดสต๊อกแล้วหรือยัง

ฝั่งคนอ่าน: หน้ารายวัน (ใบเดียว) + มุมมองรายเดือน — ลูกค้าต่อวัน · ยอดต่อหัว · เงินขาด/เกินสะสม · ปัญหาที่ยังเปิดค้าง · เทียบวันเดียวกันของสัปดาห์ก่อน ๆ

ต้องมีตารางใหม่ (เช่น daily_close + daily_issue) = migration — จะขออนุมัติพร้อม mockup

4. ต้องให้คุณ Kong ตัดสินใจก่อนทำ mockup

A. "กลุ่มลูกค้า" หมายถึงอะไร

① ช่องทาง — นั่งร้าน / กลับบ้าน / Grab / LINE MAN / ShopeeFood (ตรงกับที่ระบบมีที่เก็บอยู่แล้ว ไฟล์แบบรายบิลอาจเติมให้เอง)
② ประเภทคน — ครอบครัว / พนักงานออฟฟิศ / นักท่องเที่ยว / ขาประจำ (ต้องให้คนกะเอา)
③ ร้านตั้งรายการกลุ่มเอง (ค่าเริ่มต้น = ช่องทาง) — แนะนำ เพราะร้านต่างกันจริง (ตามหลัก "ความต่างของร้าน = setting")

B. รวม "คีย์ยอดปิดร้าน" เข้ารายงานนี้ไหม

ใช่ (แนะนำ) — กรอกที่เดียว แดชบอร์ดเปลี่ยนเป็นปุ่ม "ปิดร้านวันนี้" · กติกา ADR 0020 เดิม (ไฟล์เข้าแล้วยอดล็อก) ยังอยู่
ไม่ — แยกกัน (เสี่ยงซ้ำแบบที่ B9 เพิ่งแก้)

C. รูปถ่าย

เฟสแรกยังไม่มีรูป เว้นช่องไว้ แล้วทำที่เก็บไฟล์เป็นงานแยก (ใช้ร่วมกับรูปสินค้า/เมนู/หลักฐานโอนที่รออยู่) — แนะนำ เพราะต้องเลือกผู้ให้บริการ + dependency ใหม่ + แก้ .env
ทำที่เก็บไฟล์ก่อน แล้วค่อยทำรายงานนี้

D. ต้องการแยกช่วงเวลา (กลางวัน / เย็น) ไหม

ไม่ในเฟสแรก — ร้านเล็กส่วนใหญ่ปิดยอดวันละครั้ง (แนะนำ)
แยก — กรอกลูกค้าและเงินสองรอบต่อวัน
