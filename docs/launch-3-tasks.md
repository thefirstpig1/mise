## ⚠️ อ่านก่อนเริ่ม — สองอย่างที่พลาดง่ายที่สุด

**1. Region ต้องเป็น Singapore เท่านั้น** ทุกการอ่านของ Mise เปิด transaction ของตัวเอง หนึ่งหน้าจึงใช้ ~15 round trip · สิงคโปร์ = ~40 ms/หน้า · สหรัฐฯ = **~3.5 วินาที/หน้า** และมันจะดูเหมือนโค้ดห่วยทั้งที่เป็นระยะทางล้วน ๆ

**2. รหัสผ่าน `mise_app` มีอยู่สองที่และต้องตรงกันเป๊ะ** — อยู่ใน `DATABASE_URL` และอยู่ใน `MISE_APP_DB_PASSWORD` · สคริปต์ตอน deploy จะ**ปฏิเสธ**ถ้าไม่ตรง (ดีกว่าปล่อยให้ deploy ขึ้นไปแล้วเปิดหน้าแรกไม่ได้) แต่รู้ไว้ก่อนจะเสียเวลาน้อยกว่า

## Task 1 — สร้าง Neon **โปรเจกต์ใหม่**

### ทำไมต้องโปรเจกต์ใหม่ ไม่ใช่ branch

branch คัดลอกข้อมูลจากพ่อแม่ โปรดักชันจะมีเศษข้อมูลเทสต์ติดมาตั้งแต่วันแรก · แต่เหตุผลที่หนักกว่าคือ**รัศมีความเสียหาย**: `pnpm db:reset --force` กับ `pnpm test:sweep` เขียนกำกับไว้ว่า "dev branch only" และมันลบทั้งฐานข้อมูล

- **คนละ branch ในโปรเจกต์เดียวกัน** = ชี้ผิดคือพิมพ์ผิดตัวเดียว
- **คนละโปรเจกต์** = ต้องไปเอา credential คนละชุดมาวางเอง ซึ่ง**เกิดโดยบังเอิญไม่ได้**

แพลนฟรีให้ 100 โปรเจกต์ การแยกจึงไม่มีค่าใช้จ่าย

### ขั้นตอน

1. เข้า https://console.neon.tech → **New Project**
2. **Name:** `mise-production` (หรืออะไรที่อ่านแล้วรู้ว่าไม่ใช่ dev)
3. 🔴 **Region: `AWS ap-southeast-1` (Singapore)** — ห้ามพลาดข้อนี้
4. Postgres version: ค่า default ได้เลย
5. กด Create

### เอา connection string มา 2 อัน

ในหน้า **Connection Details** จะมีสวิตช์ **Pooled connection**

| ต้องการ | สวิตช์ | สังเกตจาก |
|---|---|---|
| **pooled** | เปิด | ใน hostname มีคำว่า `-pooler` |
| **direct** | ปิด | ใน hostname **ไม่มี** `-pooler` |

ก๊อปทั้งสองอันเก็บไว้ ทั้งคู่ตอนนี้เป็น user `neondb_owner`

> 📌 **อย่าเพิ่งรัน migration หรือ seed อะไรทั้งนั้น** — ตอน deploy Fly จะรันให้เองก่อนเวอร์ชันใหม่ขึ้น (`release_command`) และมันสร้าง role `mise_app` ให้ในขั้นตอนนั้นด้วย

## Task 2 — บัญชี Fly + **ตั้งชื่อแอป**

### ชื่อแอปคือส่วนที่ต้องคิด

- ชื่อ Fly **ไม่ซ้ำกันทั้งโลก** ใครจองก่อนได้ก่อน
- ใช้ได้แค่ **ตัวพิมพ์เล็ก ตัวเลข และขีดกลาง**
- มันกลายเป็น URL ทันที: `https://<ชื่อ>.fly.dev`
- 🔴 **`AUTH_URL` ต้องตรงกับชื่อนี้เป๊ะ** — magic link คือ URL ลิงก์ที่ชี้ผิด host คือ login ที่ไม่มีใครทำสำเร็จ
- ตอนนี้ `fly.toml` ใส่ `mise-th` ไว้เป็นค่าตั้งต้น เปลี่ยนได้

> **ที่อยู่นี้ตั้งใจให้เป็นของชั่วคราว** (ADR 0033 Consequence 5) วันที่ย้ายไปโดเมนจริง ลิงก์เก่าจะพัง — **ต้องทำตอนที่ยังมีผู้ใช้คนเดียว** ไม่ใช่ตอนมีร้านแล้ว ฉะนั้นไม่ต้องคิดชื่อให้สวยเกินไป

### ขั้นตอน

1. สมัคร https://fly.io/app/sign-up — **ต้องผูกบัตรเครดิต** แม้เครื่องเล็ก (Fly ใช้บัตรกันสแปม)
2. ติดตั้ง flyctl (PowerShell):
   ```powershell
   iwr https://fly.io/install.ps1 -useb | iex
   ```
   ปิดแล้วเปิด terminal ใหม่ แล้วเช็ค: `fly version`
3. ล็อกอิน:
   ```powershell
   fly auth login
   ```
4. จองชื่อ — **คำสั่งนี้จะ error ถ้าชื่อโดนจองแล้ว ซึ่งเป็นวิธีเช็คที่ง่ายที่สุด**:
   ```powershell
   fly apps create <ชื่อที่คิดไว้>
   ```
   ⚠️ **อย่าใช้ `fly launch`** — มันจะเขียน `fly.toml` ทับ และไฟล์นั้นมีการตัดสินใจของ ADR อยู่ทุกบรรทัด

## Task 3 — สร้างรหัสผ่านของ role `mise_app`

รหัสนี้ถูกเอาไปวางใน SQL string literal ตอนสร้าง role **ชุดอักขระจึงถูกจำกัดโดยตั้งใจ**: `A-Z a-z 0-9 . _ ~ + -` เท่านั้น ยาว 8–200 ตัว · สคริปต์จะปฏิเสธถ้าหลุดชุดนี้ (ปฏิเสธ ดีกว่า escape ให้ฉลาดแล้วพลาด)

PowerShell — ได้ตัวอักษรกับตัวเลขล้วน 40 ตัว ปลอดภัยแน่นอน:

```powershell
-join ((48..57) + (65..90) + (97..122) | Get-Random -Count 40 | ForEach-Object { [char]$_ })
```

เก็บไว้ **อย่าเพิ่งใส่ที่ไหน** เดี๋ยวผมใส่ให้ทั้งสองที่พร้อมกัน

## แล้วผมทำอะไรต่อ

พอ Kong ส่งของสามอย่างมา (2 connection string · ชื่อแอป · รหัสผ่าน) ผมจะ:

1. แก้ `fly.toml` ให้ `app` = ชื่อจริง
2. `fly secrets set` ทั้ง 11 ตัว — **`DATABASE_URL` ต้องประกอบเอง**: เอา pooled string มาแล้วเปลี่ยน `neondb_owner:<รหัสเจ้าของ>` เป็น `mise_app:<รหัสใหม่>` เพราะแอปต้องต่อในฐานะ role ที่**อยู่ใต้ RLS** (Part 30) ไม่ใช่เจ้าของตาราง
3. `fly deploy`
4. ดู `fly logs` ว่าคำเตือน single-instance ขึ้น **machine id เดียว**
5. ให้ Kong เปิด `https://<app>.fly.dev/login` **จากมือถือ** แล้วเข้าระบบจริง

### 🔴 ตอนทดสอบ login ต้องใช้อีเมลของ Kong เท่านั้น

Resend ยังไม่ได้ verify โดเมน (นั่นคือหมุด B) **วันนี้มันส่งถึงได้แค่อีเมลเจ้าของบัญชี Resend** ถ้าลองด้วยอีเมลอื่นจะไม่มีจดหมายมา และมันจะดูเหมือนระบบพัง

### สิ่งที่จะเกิดขึ้นตอน deploy ครั้งแรก (จะได้ไม่ตกใจ)

Fly รัน `release_command` **ในอิมเมจใหม่ ก่อนเวอร์ชันใหม่รับทราฟฟิก** ตามลำดับนี้:

1. `prisma migrate deploy` — สร้างตารางทั้งหมดจาก 27 migration
2. `node scripts/apply-manual-sql.mjs` — 19 ไฟล์: partial unique index, GIN/trigram, `pg_trgm`, **ข้อมูลอ้างอิงกลาง (หน่วยนับ + ความหนาแน่นของเหลว)**, RLS policy 47 อัน **และสร้าง role `mise_app` พร้อมตั้งรหัสให้**

ถ้าขั้นไหนพัง **deploy ถูกยกเลิกทั้งหมด** และเวอร์ชันเก่ายังวิ่งอยู่ (ครั้งแรกคือไม่มีอะไรขึ้นเลย) — เป็นพฤติกรรมที่ตั้งใจ ไม่ใช่ความผิดพลาด · อ่านสาเหตุจาก output ของ `fly deploy` หรือ `fly logs`
