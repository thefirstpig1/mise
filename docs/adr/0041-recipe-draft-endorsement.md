# ADR 0041 — ร่างสูตรจากครัว: เสนอ → รับรอง → นำไปใช้จริง

**Status:** accepted · **Date:** 2026-10-05 · **Decided by:** Kong (chat, 2026-10-05)
**Part:** 41 · migration `20261005120000_part_41_draft_endorsement` (3 คอลัมน์บน `recipe` · ไม่มีตารางใหม่)
**แก้ต่อจาก:** ADR 0025 (Menu Lab) · ADR 0029 (สิทธิ์เป็น capability) · การแบ่งสิทธิ์ "แก้ของที่ทุกสาขาใช้ร่วม" (Kong 2026-10-04)

## Context
หน้าทดลองเมนูใหม่ทำให้เห็นช่องว่าง: คนที่ร่างได้แต่ "เผยแพร่" ไม่ได้ ร่างแล้วไม่มีทางบอกใคร และหัวหน้าไม่รู้ว่ามีร่างรออยู่ · พนักงานครัว — คนที่รู้สูตรจริงที่สุด — เข้าหน้าทดลองเมนูไม่ได้เลย เพราะไม่มี `recipe:write` · Kong: *"พนักงานครัวร่างได้ เผยแพร่เองไม่ได้ … area manager ร่างเองได้เผยแพร่เองได้ ผู้จัดการสาขาสามารถ approve หรือให้เครดิตยืนยันร่างที่พนักงานครัวร่างขึ้นมาได้และแก้ไขได้"*

## Decision

**1. Capability ใหม่ `recipe:draft`** — ร่างและเสนอสูตรในทดลองเมนู ไม่มีอะไรที่ตัดสต๊อกหรือเปลี่ยนต้นทุน · `kitchen_staff` (และ `dept_head` ที่สืบมา) ได้ตัวนี้ **โดยไม่ได้ `recipe:write`** · ทุก role ที่มี `recipe:write` มี `recipe:draft` ด้วย
*(ปฏิเสธ: ให้พนักงานครัว `recipe:write` — ได้สิทธิ์แก้สูตรที่ตัดสต๊อกอยู่ในหน้าจัดการเมนูไปด้วย)*

**2. สถานะของร่าง `draft_status`: DRAFT → SUBMITTED (เสนอ) → ENDORSED (รับรอง)** · NULL บนสูตรที่ไม่ใช่ร่าง · ปุ่มคือ "เสนอสูตรนี้" (Kong: คำว่า "ส่งให้หัวหน้าดู" แปลก ใช้ "ส่ง" หรือ "เสนอ")

**3. "เผยแพร่" เปลี่ยนชื่อเป็น "นำไปใช้จริง"** (Kong อนุมัติ)

**4. ใครทำอะไรได้**

| | ร่าง / แก้ร่าง | เสนอ | รับรอง | นำไปใช้จริง |
|---|---|---|---|---|
| `recipe:draft` อย่างเดียว (พนักงานครัว) | เฉพาะร่างของตัวเอง | ✅ | – | – |
| `recipe:write` สาขาเดียว (ผู้จัดการสาขา) | ทุกร่าง | – | ร่างของคนอื่น | **เฉพาะสาขาในขอบเขต** — เป็นสูตรของสาขานั้นตั้งแต่วันนี้ (เหมือน "เฉพาะสาขานี้" ในหน้าจัดการเมนู) แล้วร่างหายไป |
| `recipe:write` + ดูแลทุกสาขา (area manager · ส่วนกลาง · เจ้าของ) | ทุกร่าง | – | ร่างของคนอื่น | ทุกสาขา (สูตรกลาง) |

**5. การรับรองเป็นเครดิต ไม่ใช่ด่าน** (Kong เลือกข้อเสนอ) — คนที่นำไปใช้ทุกสาขาได้ ไม่ต้องรอใครรับรอง เพื่อไม่ให้ร้านเล็กที่ไม่มีผู้จัดการสาขาติด · รับรองร่างของตัวเองไม่ได้ (คำรับรองคือคำของคนอื่น)

**6. คำรับรองรับรองสิ่งที่ผู้รับรองอ่าน** — ร่างที่รับรองแล้วถูกแก้โดย**คนอื่น**ที่ไม่ใช่ผู้รับรอง → กลับเป็น SUBMITTED และล้างชื่อผู้รับรอง · ผู้รับรองแก้เองไม่ล้าง

**7. `created_by` ของร่างคือ "ผู้ร่าง" และไม่เปลี่ยนตามคนแก้ล่าสุดอีก** — เดิม `updateDraftLogic` เขียนทับด้วยคนแก้ ซึ่งทำให้เครดิต "ร่างโดย" หายทันทีที่หัวหน้าแตะ

**8. คนที่ร่างรออยู่ต้องรู้** — แถบ "มีร่างสูตรรอคุณ N รายการ" บนแดชบอร์ดและหัวหน้าทดลองเมนู: ร่าง SUBMITTED ของคนอื่นสำหรับคนที่มี `recipe:write` · บวก ENDORSED สำหรับคนที่นำไปใช้ทุกสาขาได้

## Consequences
1. migration เพิ่ม `draft_status` (enum `RecipeDraftStatus`), `endorsed_by` (FK → `app_user`, ON DELETE SET NULL), `endorsed_at` · ร่างที่มีอยู่ backfill เป็น DRAFT · RLS ของ `recipe` คลุมอยู่แล้ว
2. การนำไปใช้ที่สาขาเดียวทำสองธุรกรรม (บันทึกสูตรสาขาก่อน แล้วค่อยลบร่าง) — กดซ้ำหลังครึ่งแรกสำเร็จจะเจอสูตรเดิมด้วย `submitKey` เดิมไม่ได้ เพราะหน้าจอสร้าง key ใหม่ทุกครั้ง: ผลคือสูตรสาขาถูกแก้ซ้ำด้วยเนื้อหาเดียวกัน (เป็นเวอร์ชันใหม่วันเดียวกัน = correction) ไม่เสียหาย
3. พนักงานครัวไม่มี `cost:view` จึงร่างโดยไม่เห็นต้นทุนและไม่มีตัวช่วยตั้งราคา — ตั้งใจ: ราคาเป็นงานของหัวหน้า
4. หน่วยตวงมาตรฐานที่ร่างเลือกถูกสร้างบนสินค้าได้ด้วย `recipe:draft` (เป็นข้อเท็จจริงเรื่องขนาด) · หน่วยที่ร้านตั้งเองยังต้องดูแลทุกสาขา
5. ยังไม่มีการแจ้งเตือนนอกแอป (อีเมล/ไลน์) — แถบบนแดชบอร์ดคือช่องทางเดียว
