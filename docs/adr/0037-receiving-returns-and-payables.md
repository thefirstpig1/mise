# ADR 0037 — ตีกลับ คืนของ จับคู่บิล และเจ้าหนี้ค้างจ่าย

**Status:** accepted · **Date:** 2026-09-29 · **Grill:** Q1–Q8 (Kong, 2026-09-29)
**Part:** ยังไม่จัด (ต้องมาหลังระบบเก็บรูป และหลังหัวข้อ "สิทธิ์ที่ร้านตั้งเอง") · **แก้** ADR 0013 (บรรทัดใบรับมีส่วนตีกลับ · คืนของบางส่วนด้วยบรรทัดกลับรายการ) และ ADR 0016 (ค่าใช้จ่ายติดลบจากการคืนของ · การจ่ายและผู้จ่าย) · **มี migration** · **ต้องมีระบบเก็บรูป (Tigris) ก่อน**

## Context

Kong เล่าเหตุการณ์จริงที่หน้าร้าน: *"ตีกลับ ของมาไม่ครบ คืนของ ขนส่งต้องนำบิลกลับไปปรับยอด … ถ้าขนส่งกลับมาพร้อมบิลใหม่ ของใหม่บางส่วนในวันพรุ่งนี้ ยอดที่พนักงานรับของตรวจสอบก็อาจจะลืมไปแล้วว่าเมื่อวานได้รับอะไร"* แล้วตามด้วยงานของฝ่ายบัญชี: สำรองจ่าย เคลียร์ยอด แนบสลิป รู้ว่าบิลไหนยังไม่จ่าย และ *"ค้างจ่ายจนสั่งของไม่ได้ … เซลล์ไม่รับออเดอร์"*

ข้อเท็จจริงจากโค้ด:
- บรรทัดใบรับมีแค่ **จำนวนที่รับ** — "มาถึงแต่ไม่รับ" กับ "ไม่ได้มาส่ง" แยกกันไม่ออก
- แก้ของหลังรับได้สองทาง และผิดทั้งคู่: **ยกเลิกทั้งใบ** (บรรทัดที่ดีหายด้วย) หรือ **ลงของเสีย** (เงินที่ผู้ขายต้องคืนหายจากตัวเลข)
- ค่าใช้จ่ายหนึ่งใบต่อใบรับหนึ่งใบ ลงวันที่ = **วันรับของ** และ `/cost`, P&L นับตามวันนั้น — **ระบบใช้เกณฑ์คงค้างอยู่แล้ว**
- การจ่ายคือสถานะ จ่ายแล้ว/ยังไม่จ่าย บนค่าใช้จ่าย ไม่มีหลักฐาน ไม่รู้ว่าใครจ่าย
- เงื่อนไขชำระเงินของผู้ขายเป็นข้อความอิสระ คำนวณวันครบกำหนดไม่ได้
- พนักงานครัว **ไม่มีสิทธิ์รับของ** จึงบันทึก "วิ่งไปซื้อที่ตลาด" ไม่ได้

## Decision

### Q1 — ตีกลับที่หน้าร้านเป็นส่วนหนึ่งของบรรทัดใบรับ
บรรทัดใบรับมี **รับไว้** และ **ตีกลับ (จำนวน + เหตุผล)** · ส่วนที่ตีกลับไม่เข้าสต๊อก ไม่เป็นต้นทุน · **ผู้ขายจะส่งทดแทนไหม — ค่าเริ่มต้น "ส่งทดแทน"** = ใบสั่งซื้อยังค้างรับส่วนนั้น ใบรับครั้งถัดไปขึ้นว่า "ค้างรับ 2 กก. — ส่งทดแทนของที่ตีกลับเมื่อวาน (เนื้อไม่สวย)" · "ไม่ต้องส่ง" = ตัดออกจากยอดค้าง

### Q2 — เงินที่ติดหนี้ ≠ เอกสาร: ค่าใช้จ่าย = ของที่รับไว้เสมอ, บิลจับคู่ด้วยเลขบิล
ผู้ขายไทยปรับบิลได้สี่แบบ (แก้หน้าร้าน · ใบลดหนี้ตามมา · ส่งทดแทนโดยไม่มีบิลใหม่ · ส่งทดแทนพร้อมบิลใหม่) และ **ร้านของ Kong เจอครบทั้งสี่** · วิธีเดียวที่รองรับทั้งหมด: ใบรับบันทึก **เลขบิล + ยอดตามบิล** หรือ "ใช้บิลเดิมเลขที่ …" · ฝ่ายบัญชีจับคู่ทุกใบรับที่อ้างเลขบิลเดียวกันกับยอดตามบิล · ที่ต่างคือ **เอกสารที่ยังค้าง** (ใบลดหนี้ หรือของทดแทน) ไม่ใช่ต้นทุนที่ผิด

### Q3 — ต้นทุน = วันที่ของมาถึง (เกณฑ์คงค้าง) แยกจากการจ่ายเงิน
ยืนยันสิ่งที่ระบบทำอยู่ · ของส่ง 30 ก.ย. จ่าย 5 ต.ค. = ต้นทุน ก.ย. · เพิ่ม **เจ้าหนี้ค้างจ่าย** และ **เงินสดจ่ายออก (ตามวันจ่าย)** เป็นตัวเลขแยก · ส่งทดแทนเป็นต้นทุนวันที่ของทดแทนมาถึง · ของที่ตีกลับไม่เคยเป็นต้นทุน ใบลดหนี้จึงไม่เปลี่ยนต้นทุน

### Q4 — คืนของหลังรับ อ้างบรรทัดใบรับเดิม
คืนได้ไม่เกินที่รับ (หักที่คืนไปแล้ว) · สต๊อกออกที่ **ราคาของรอบส่งนั้น** ด้วยบรรทัดกลับรายการบางส่วนในใบรับเดิม (กลไกของ ADR 0013 Q6 ที่ FIFO ตัดชั้นเดียวกันได้อยู่แล้ว) · ลง **วันที่คืนจริง** · สร้าง **ค่าใช้จ่ายติดลบ "ใบลดหนี้ค้างรับ"** วันเดียวกัน (ไม่งั้นวิธีนับสต๊อกคิดว่าของที่คืนถูกใช้ไป) · ส่งทดแทนเป็นค่าเริ่มต้น · สิทธิ์ = `receive:write`

### Q5 — จ่ายทีละบิล แนบหลักฐาน · สำรองจ่ายเป็นหนี้ต่อพนักงาน
**ไม่มีการจ่ายรวมหลายบิล** (Kong: ปกติเคลียร์เป็นบิล ๆ) · ทุกการจ่ายแนบสลิป · บิลบอก **ใครจ่าย**: ผู้ขายยังไม่ได้รับ → "ค้างจ่ายผู้ขาย" · พนักงานออกเงินเอง (สำรองจ่าย) → "รอคืนเงินพนักงาน" → บัญชีโอนคืน แนบสลิป → "เคลียร์แล้ว" · บัญชีมีสองรายการต้องเคลียร์: ค้างจ่ายผู้ขาย (ต่อผู้ขาย: กี่บิล เท่าไหร่ ครบกำหนดเมื่อไหร่) และค้างคืนพนักงาน (ต่อคน)

### Q6 — ของที่พนักงานซื้อเอง: ใบรับไม่อ้างใบสั่งซื้อ + สิทธิ์ใหม่
มีอยู่แล้ว (ADR 0013 Q1) ต้นทุน = ราคาตามใบเสร็จ · เพิ่ม **สิทธิ์ "บันทึกของที่ซื้อเอง"**: ใบรับไม่อ้างใบสั่งซื้อเท่านั้น · **เบิกได้ต้องมีทั้งรูปบิลและหลักฐานการจ่าย (สลิป)** (Kong: "ต้องมีรูปบิล แล้วก็สลิป ถึงจะเบิกได้") ขาดอย่างใดอย่างหนึ่ง = "รอหลักฐาน" บัญชีเคลียร์ไม่ได้ · ถือเป็นสำรองจ่ายของผู้บันทึกโดยอัตโนมัติ · **ค่าเริ่มต้น: พนักงานครัว หัวหน้าแผนก และสูงกว่า — ร้านเปลี่ยนเองได้** (Kong: "สิทธิ์พวกนี้ให้ร้านเป็นคนตัดสินใจเอง") ซึ่งทำให้หัวข้อ "สิทธิ์ที่ร้านตั้งเอง" ต้องมาก่อน · ตอนบันทึก แสดงบรรทัดใบขอซื้อที่ตรงกับของที่ซื้อ ให้ติ๊ก "ซื้อมาแล้ว" ปิดบรรทัดนั้น (กันจัดซื้อสั่งซ้ำ)

### Q7/Q8 — วิธีจ่ายเงินของผู้ขาย บังคับเลือกตอนเพิ่มผู้ขาย · แจ้งเตือนสองชั้น
สามแบบ: **จ่ายเมื่อของมาส่ง** (ครบกำหนด = วันรับ) · **เครดิต N วัน** · **ต้องจ่ายก่อนถึงจะส่ง** (ส่งใบสั่งซื้อแล้วบัญชีได้งาน "ต้องโอนก่อน ฿X" จ่ายแนบกับใบสั่งซื้อ ของมาแล้วบิลขึ้น "จ่ายล่วงหน้าแล้ว" ส่วนที่ส่งไม่ครบเป็นยอดที่ผู้ขายต้องคืน) · **ไม่มีค่าเริ่มต้นตอนเพิ่มผู้ขาย** (Kong: กันร้านขี้เกียจตั้งแล้วใช้แอปไม่เป็น) ผู้ขายเดิมเริ่มที่จ่ายเมื่อของมาส่ง + แถบเตือนให้ยืนยัน · วันครบกำหนดตรึงบนบิลตอนสร้าง บัญชีแก้รายบิลได้ · อายุหนี้: ยังไม่ถึงกำหนด / 1–30 / 31–60 / 60+
แจ้งเตือน: (1) **บิลเครดิตเลยกำหนด** → บัญชี สรุปวันละครั้ง (2) **ผู้ขายค้างจ่าย ≥ N ใบ และครัวกำลังสั่งจากเขา** (มีบรรทัดขอซื้อ / ตัดรอบ / ส่งใบสั่งซื้อ) → บัญชีทันที และจัดซื้อเห็นคำเตือนตอนส่ง (เตือน ไม่ห้าม) · **N = 2 ใบเป็นค่าเริ่มต้นของร้าน ตั้งรายผู้ขายได้** · ช่องทาง: แผงงานบนแดชบอร์ด + อีเมล (ยังไม่มีกระดิ่งแจ้งเตือน)

## Consequences
1. **ระบบเก็บรูปต้องมาก่อน** (สลิป ใบเสร็จ บิล) — Feature 5 เลือก Tigris ไว้แล้ว แต่ต้องมีบัญชีและ dependency ใหม่ = ต้องอนุมัติ
2. **หัวข้อ "สิทธิ์ที่ร้านตั้งเอง" ต้องมาก่อน Part ที่สร้าง ADR นี้** เพราะ Q6 ต้องการมัน
3. ค่าใช้จ่ายติดลบ (Q4) เป็นรูปแบบใหม่สำหรับ `/cost` และ P&L — ต้องทดสอบว่ายอดซื้อสุทธิของเดือนถูก
4. การจ่ายแยกเป็นเอกสารของตัวเอง (ผู้จ่าย · หลักฐาน · วันที่) ไม่ใช่สองคอลัมน์บนค่าใช้จ่ายแล้ว — ตัดสินรายละเอียดตอนวางแผน Part
5. ทะเบียนสิ่งที่ร้านตั้งเองได้ (`docs/settings-register.md`) เพิ่มสามแถวจาก ADR นี้
