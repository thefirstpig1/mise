# ADR 0031 — จดหมายที่ Mise ส่งเอง: แยกขาออกออกจากขาเข้า, SMTP ก่อน SDK, และปืนที่เพิ่งถูกบรรจุกระสุน

**Status:** accepted · **Date:** 2026-09-01 · **Grill:** Q1–Q9
**Part:** Sprint 7 Part 31 · **Unblocks** ADR 0029 (คำเชิญที่ส่งไม่ได้) · **Half-answers** ADR 0030 Consequence 5 · **Leaves standing** ADR 0020 Consequence 2 (Part 20b)

## Context

ทุกที่ในเอกสารของโปรเจกต์เขียนตรงกันว่า blocker คือ *"choosing an **inbound-mail** vendor"* — CLAUDE.md, `docs/sprint-progress.md:65`, ADR 0030 Consequence 5, ADR 0029 Q2 คำเดียว ผู้ให้บริการเดียว บล็อกทั้ง Part 20b และ magic link พร้อมกัน

**ประโยคนั้นมัดของสองอย่างที่ไม่ผูกกันทางเทคนิคเลยไว้ด้วยกัน** และผลของการมัดคือของที่จำเป็นที่สุดในระบบ — ทางเข้าเดียวของทุกคน — รอของที่ ADR 0020 Q2 เขียนเองว่าเป็น *"a bonus, never a precondition"* มาตั้งแต่ Sprint 4

ข้อเท็จจริงเก้าข้อจากการอ่านโค้ดและ `.env` ตอน grill เป็นตัวกำหนดคำตอบทั้งหมด

1. **`auth.ts:42` ปฏิเสธตรง ๆ อยู่แล้ว** — `throw new Error("Production email not configured yet (Sprint 7)")` และ `auth.ts:31` ใช้ `process.env.NODE_ENV === "development"` เป็นสวิตช์ไป `console.log`

2. **`nodemailer@6.9.16` อยู่ใน `dependencies` แล้ว พร้อม `@types/nodemailer` ใน dev — และ `grep` ทั้ง `src/` เจอ 0 จุดที่ใช้** มันติดมากับ next-auth ไม่ใช่ของที่เคยถูกเลือก

3. **Sprint 0 เดาทางไว้แล้วและไม่เคยเดินต่อ** — `.env.example` มี `EMAIL_SERVER_HOST / PORT / USER / PASSWORD` ครบชุดแบบ SMTP ตั้งแต่ 2026-06-07 และ `.env` มี `EMAIL_FROM` ที่**ไม่มีใครอ่านเลยสักบรรทัด**

4. **ไม่มี deployment target อยู่ในโปรเจกต์เลย** — ไม่มี `vercel.json` ไม่มี Dockerfile ไม่มี `.github/` · `docker-compose.yml` เป็น Postgres local ที่ Sprint 0 ทิ้งไปแล้ว · `AUTH_URL="http://localhost:3000"` · ไม่มีชื่อโดเมนปรากฏที่ไหนในโปรเจกต์

5. **`inviteMember` ไม่ส่งอะไรถึงคนที่ถูกเชิญเลย** — `settings/members/actions.ts:150` ขึ้นข้อความว่า `เชิญ … แล้ว — เข้าใช้งานได้ทันทีเมื่อล็อกอินด้วยอีเมลนี้` ซึ่งขึ้นให้**เจ้าของร้านอ่าน** คนที่ถูกเชิญไม่มีทางรู้ว่ามีร้านรออยู่ เว้นแต่มีคนไปบอกปากเปล่า

6. **`/login` เป็นฟอร์มสาธารณะที่ทำให้ Mise ส่งเมลไปที่อยู่ใดก็ได้ ไม่จำกัดจำนวน** (`login/page.tsx:35`) และ `grep` หา rate limit ทั้ง `src/` ได้ 0 จุด ไม่มี `middleware.ts` ด้วย

7. **`verification_token` มีแค่ `identifier / token / expires` — ไม่มี `createdAt`** (`schema.prisma:56`)

8. **`auth.ts:46` ตั้ง `pages` ไว้แค่ `signIn` กับ `verifyRequest` ไม่มี `pages.error`** ทางที่ผิดพลาดจึงตกไปที่หน้าดีฟอลต์ภาษาอังกฤษของ Auth.js ที่ `/api/auth/error`

9. **ทางส่งมีคนเรียกแค่สองที่** — `login/page.tsx:36` และ `signup/page.tsx:35` · **ชุดเทสต์ไม่แตะเลย** เมลจริงจึงหลุดออกจาก `vitest` ไม่ได้

## Decision

### Q1 — ขาออกกับขาเข้าเป็นคนละการตัดสินใจ และปลดล็อกเฉพาะขาออก

|  | ขาออก (magic link) | ขาเข้า (Part 20b) |
|---|---|---|
| ใครพึ่งมัน | **ทุกการล็อกอิน** + คำเชิญทั้งหมดของ Part 29 | pulse อัตโนมัติ |
| ADR ว่าไว้ว่าจำเป็นแค่ไหน | ADR 0029: คำเชิญ **คือ** magic link ไม่มีทางอื่น | ADR 0020 Q2: *a bonus, never a precondition* |
| ถ้าไม่มี | ไม่มีใครล็อกอินเข้า production ได้แม้แต่ Kong | แคชเชียร์พิมพ์เอง 5 วินาที = ดีไซน์ปัจจุบัน |
| ต้องการอะไร | โดเมนที่ verify SPF/DKIM | โดเมนที่ตั้ง **MX record** + vendor ที่มี inbound parse |

การเลือก vendor โดยเอา "ต้องรับเมลเข้าได้ด้วย" เป็นเงื่อนไข คือการตัดตัวเลือกขาออกที่ดีที่สุดทิ้งเพื่อ feature ที่ ADR ของมันเองบอกว่าไม่จำเป็น และถ้าวันหนึ่งอยากได้ขาเข้าจริง ๆ มันใช้คนละเจ้าได้ — MX ชี้ subdomain แยก (`pulse.<domain>`) ไม่แตะ SPF/DKIM ของโดเมนที่ใช้ส่ง

**Part 20b ยังบล็อกอยู่เหมือนเดิม และนั่นคือเจตนา** ไม่ใช่ของที่ Part นี้ลืม

### Q2 — magic link คือ URL และยังไม่มี URL: Part นี้คือ A ไม่ใช่ C

ข้อเท็จจริง 4 บอกว่าเมลที่ส่งสวยแค่ไหน ถ้าลิงก์ข้างในชี้ `localhost:3000` ก็ตายตั้งแต่เปิดบนมือถือคนอื่น สิ่งที่บล็อก *production login* จริง ๆ ไม่ใช่อีเมล — **มันคือยังไม่มี production**

| | ทำอะไร | ต้องมีอะไรก่อน |
|---|---|---|
| **A** ← Part นี้ | เอา `throw` ออก ต่อ Resend จริง ส่งเมลจริง พิสูจน์ด้วยการที่เมลถึงกล่องจริง | สมัคร vendor + `.env` |
| **B** | verify โดเมน ส่งจาก `noreply@<domain>` ส่งถึงคนอื่นได้ | Kong ซื้อโดเมน |
| **C** | deploy จริง + `AUTH_URL` จริง = คำเชิญ Part 29 ใช้ได้จริง | เลือกที่ deploy · รัน `enforce_rls.sql` บน branch นั้น · หมุนรหัสผ่าน |

**A ไม่ล็อกอะไรไว้เลย** — A→B คือแก้ `EMAIL_FROM` หนึ่งบรรทัด, B→C คือ `AUTH_URL` อีกบรรทัด และ **vendor ที่ยังไม่เคยส่งเมลผ่านมันจริง คือ vendor ที่ยังไม่ได้เลือก แค่อ่านมา** — A คือขั้นที่ทำให้การเลือกเป็นสิ่งที่พิสูจน์ได้ ตรงกับ practice ที่โปรเจกต์นี้ยึด: *เขียวยังไม่นับจนกว่าจะเคยเห็นมันแดง*

⚠️ **จบ Part นี้แล้วยังไม่มีใครล็อกอินเข้า production ได้ เพราะยังไม่มี production** C คือ Part เรื่อง deployment ไม่ใช่ Part เรื่องอีเมล และควรถูกเรียกด้วยชื่อนั้น

### Q3 — SMTP ผ่าน nodemailer ที่มีอยู่แล้ว ไม่ใช่ HTTP SDK ของ vendor

|  | SMTP (nodemailer) | HTTP SDK |
|---|---|---|
| dependency ใหม่ | **ไม่มี** | มี → 🛑 stop-and-ask |
| เปลี่ยน vendor | **แก้ `.env` ล้วน ๆ** — Resend / Postmark / SES / Brevo พูด SMTP หมด | เขียนใหม่ + สลับ dependency |
| error ตอนพัง | รหัส SMTP ดิบ อ่านยากกว่า | ข้อความ vendor + message id |
| ตอน deploy (ยังไม่เลือก host) | ⚠️ serverless บางเจ้ากั๊ก port ขาออก · connection ค้างไม่เข้ากับ function ที่ตายทุกครั้ง | ไม่แคร์ host |

**เหตุผลหลักข้อเดียวและมันหนัก: มันทำให้ Q4 กลายเป็นการตัดสินใจที่ย้อนกลับได้ด้วยการแก้ `.env`** grill นี้เกิดขึ้นเพราะการเลือก vendor ถูกมองว่าใหญ่เกินกว่าจะเดาแล้วเดินต่อ — transport ที่ทำให้ vendor เป็นแค่ hostname ทำให้ความใหญ่นั้นหายไป และเราได้ *ลอง* แทนที่จะ *เถียง*

รองลงมา: ข้อเท็จจริง 2 และ 3 — ของที่ติดตั้งไว้แล้วและไม่ได้ใช้ กลายเป็นของที่ใช้ และตรงกับสิ่งที่ Sprint 0 เดาไว้พอดี

### Q4 — Resend

- มี **SMTP endpoint** ตรง ๆ ไม่ต้องใช้ SDK ของเขา (ตรงกับ Q3)
- **ทำ A ได้โดยไม่ต้องมีโดเมน** — ส่งจากที่อยู่ sandbox ไปหาอีเมลเจ้าของบัญชี
- free tier กว้างพอไปไกลกว่า Beta มาก — Mise ส่งเฉพาะ magic link ร้านหนึ่งร้าน 5 คน = หลักสิบฉบับ/เดือน
- ข้างใต้เป็น Amazon SES จึงได้ deliverability ระดับ SES โดยไม่ต้องเจ็บกับการตั้ง SES
- A→B คือเพิ่ม DNS record ชุดเดียว ไม่แตะโค้ด

**ปฏิเสธพร้อมเหตุผล:** **Amazon SES ตรง ๆ** — ออกจาก sandbox ต้องยื่นเรื่องให้ support อนุมัติ กินเวลาเป็นวันและถูกปฏิเสธได้ คือ blocker แบบเดียวกับที่ Part นี้กำลังกำจัด และปริมาณของ Mise ทำให้ส่วนต่างราคาเป็นหลักสตางค์ · **Gmail / Workspace SMTP** — จำกัดปริมาณ ถูกมองเป็นพฤติกรรมน่าสงสัย ไม่ใช่ของสำหรับ app · **SendGrid** — DX เก่า และมีประวัติระงับบัญชีผู้ส่งรายเล็กโดยไม่เตือน ซึ่งกับทางเข้าเดียวคือความเสี่ยงที่ไม่คุ้ม

**คู่แข่งจริงข้อเดียวคือ Postmark** และเหตุผลของมันถูกต้อง: ใน Mise **อีเมลคือทางเข้าเดียว ไม่มีรหัสผ่านสำรอง** เมลตกกล่องขยะ = ล็อกอินไม่ได้เลย Postmark ขึ้นชื่อเรื่อง inbox placement ของ transactional ที่สุดและแยก stream ไม่ให้ marketing ปนกับ login ถ้าวันหนึ่ง deliverability ของ Resend ไม่พอ **นี่คือชื่อที่ต้องหยิบก่อน** และเพราะ Q3 การหยิบคือแก้ `.env`

⚠️ ตัวเลข free tier ราคา และเงื่อนไข sandbox ในหน้านี้มาจากความรู้ถึงพฤษภาคม 2026 — **ต้องยืนยันจากหน้าเว็บจริงก่อนเขียนโค้ดบรรทัดแรก** ถ้า "ส่งได้โดยไม่ต้องมีโดเมน" ไม่จริงแล้ว A จะทำไม่ได้ตามที่ออกแบบ และต้องกลับมาคุยกันใหม่

### Q5 — คำเชิญได้จดหมายแจ้ง และมันไม่ใช่ credential ใบที่สอง

ข้อเท็จจริง 5: คำเชิญวันนี้เงียบสนิทสำหรับคนที่ถูกเชิญ **และเคสที่มันพังคือเคสที่ CONTEXT.md เขียนชื่อไว้เอง** — บรรทัด 140 นิยาม [Active shop] ว่ามีความหมายกับ *"an outside bookkeeper, or someone invited to a second shop"* คือคนที่**ไม่ได้ยืนอยู่ในร้าน** ซึ่งเป็นคนที่ "เดี๋ยวเจ้าของไปบอกเอง" ใช้ไม่ได้

**ADR 0029 Q2 ไม่ได้ห้ามข้อนี้** มันปฏิเสธ *token / credential ใบที่สอง* ที่ต้องดูแล หมดอายุ เพิกถอน — จดหมายแจ้งไม่พกอะไรที่ใช้เข้าระบบได้เลย ไม่มีอะไรให้หมดอายุ ไม่มีอะไรให้เพิกถอน

**สามเส้นที่ล้อมมันไว้:**

1. **ไม่พก credential** — ไม่มี token ไม่มีลิงก์ที่ล็อกอินได้ในตัว ชี้ไป `/login` เฉย ๆ ให้เขาขอ magic link เอง ซึ่ง**คือการยอมรับตาม ADR 0029**
2. **ส่งหลังแถว commit แล้ว ไม่ใช่ในทรานแซกชัน** — SMTP ล่มใน tx จะ rollback คำเชิญที่ไม่ได้ผิดอะไร (บทเรียนเดิม: ทรานแซกชันย้อนสิ่งที่มันบันทึกไว้เอง)
3. **ส่งไม่ผ่าน = คำเชิญยังอยู่ และหน้าจอพูดความจริง** — `เชิญแล้ว แต่ส่งอีเมลแจ้งไม่สำเร็จ` ไม่ใช่เงียบแล้วปล่อยให้เจ้าของเข้าใจว่าเขาได้รับแล้ว

### Q6 — `/login` คือปืนยิงอีเมลที่ไม่มีใครถือกุญแจ และกระสุนเพิ่งถูกบรรจุ

ข้อเท็จจริง 6 เป็นจริงมาตั้งแต่ Sprint 0 แต่**ไม่เป็นอันตรายเพราะ dev แค่ log** — ความเสี่ยงเกิดขึ้นพร้อมกับสวิตช์ที่ Part นี้เปิดพอดี มันจึงเป็นของ Part นี้ ไม่ใช่ scope creep

และของที่เสียหายไม่ใช่ค่าส่งเมล:

> ส่งเมลที่ไม่มีใครขอออกจากโดเมนเรา → คนกด "นี่คือสแปม" → deliverability ตก → **magic link คือทางเข้าเดียว** → ร้านที่จ่ายเงินล็อกอินไม่ได้
>
> คนที่โจมตีไม่เจ็บ **ผู้ใช้จริงเป็นคนเจ็บ** และชื่อเสียงโดเมนซ่อมช้ามาก นี่คือคุณสมบัติ "ย้อนกลับยาก" ตัวจริงของทั้ง ADR นี้

**สองชั้น เพราะมันอยู่คนละที่และเลือกได้คนละเวลา**

**ชั้น 1 — ต่อที่อยู่อีเมล · Part นี้ · ไม่มี migration.** นับแถวใน `verification_token` ที่ `identifier` เดียวกันและยังไม่หมดอายุ เกิน N ใบที่ยังไม่ถูกใช้ → ไม่ส่งเพิ่ม (Auth.js ลบ token เมื่อถูกใช้ "ค้างหลายใบ" จึงแปลว่าไม่มีใครกดจริง) ตารางมีอยู่แล้ว ไม่มีคอลัมน์ใหม่ — แบบเดียวกับที่ Part 27 ทำทั้ง Part
⚠️ ข้อเท็จจริง 7: ตารางนี้**ไม่มี `createdAt`** เพราะ `maxAge` คงที่ 24 ชม. `expires` จึงเรียงลำดับเท่ากับเวลาสร้าง ใช้ได้ แต่เป็นการอ่านเวลาสร้างจากคอลัมน์ที่ไม่ได้ตั้งใจให้อ่านแบบนั้น — **ต้องมีคอมเมนต์กำกับ ไม่ทำเงียบ ๆ** และถ้าวันไหน `maxAge` เปลี่ยน ตรรกะนี้ผิดทันที

**ชั้น 2 — ต่อผู้เรียก (IP) · ยังไม่ทำ · เป็นของค้างของ Part deployment.** ชั้น 1 **ไม่กัน**การโจมตีที่ทำลายชื่อเสียงจริง คือยิงไป 10,000 ที่อยู่ ที่ละครั้ง — ต่อ identifier ไม่มีอันไหนเกินลิมิต ของที่กันได้ต้องมีที่เก็บ (= ตารางใหม่ = 🛑) **หรือ**ทำที่ชั้น host/edge ซึ่งเป็นที่ที่มันควรอยู่ และ **เลือกไม่ได้จนกว่าจะรู้ว่า deploy ที่ไหน** (Q2)

🔴 **ชั้น 2 ต้องมีก่อน verify โดเมน (B) ไม่ใช่ก่อน deploy (C)** — ช่องโหว่เปิดตอนโดเมนพร้อมส่งหาคนนอก ไม่ใช่ตอนมี URL จริง การปล่อยโดเมนที่ verify แล้วเปิดโล่งแม้อาทิตย์เดียวคือวิธีที่โดเมนถูกเผาทิ้ง

### Q7 — สวิตช์คือ "มี credential ไหม" ไม่ใช่ "อยู่โหมดไหน"

ข้อเท็จจริง 1: สวิตช์วันนี้คือ `NODE_ENV` ซึ่งแปลว่าการพิสูจน์ A ต้องรันเครื่องตัวเองในโหมด production — เปลี่ยนพฤติกรรม Next ทั้งชุดเพื่อทดสอบอย่างเดียว

|  | มี SMTP config | ไม่มี |
|---|---|---|
| **dev** | **ส่งจริง** ← ทางพิสูจน์ A | `console.log` เหมือนเดิม |
| **production** | ส่งจริง | **`throw`** (ยังโยน แต่เปลี่ยนข้อความ) |

1. **การมีรหัสอยู่ในมือ *คือ* เจตนา** ไม่ต้องประดิษฐ์ตัวแปรที่สามมาบอกสิ่งที่ `.env` บอกอยู่แล้ว
2. **คนที่ clone repo มาแล้วไม่มีรหัส ได้พฤติกรรมเดิมทุกอย่าง** ลิงก์ขึ้น terminal ไม่ต้องสมัคร vendor เพื่อรันโปรเจกต์
3. **ช่องขวาล่างต้องโยนต่อไป และนี่คือข้อที่สำคัญที่สุด** — production ที่ไม่มีรหัสแล้ว log เงียบ ๆ คือสองอย่างพร้อมกัน: magic link ที่ใช้ล็อกอินได้กองอยู่ใน log ของเซิร์ฟเวอร์ **และ** ผู้ใช้เห็นคำว่า "เช็คอีเมล" สำหรับเมลที่ไม่มีวันมา ปฏิเสธเสียงดังดีกว่าทั้งสองทาง

**บั๊กที่ต้องแก้พร้อมกัน:** `login/page.tsx:31` เขียนตายตัวว่า `(Dev mode — ลิงก์จะแสดงใน terminal ของ dev server)` — **กลายเป็นคำโกหกทันทีที่สวิตช์ถูกเปิด** ผู้ใช้จริงจะถูกบอกให้ไปดู terminal หน้าจอนี้ต้องพูดตามช่องในตารางเดียวกัน

### Q8 — จดหมายแจ้งเปลี่ยนการพิมพ์ผิดจากของเงียบ เป็นคำเชิญที่ส่งถึงคนแปลกหน้าจริง

ตาม ADR 0029 คำเชิญคือแถว membership ที่ผูกกับ *ข้อความอีเมล* และไม่มีขั้นตอนยอมรับ แปลว่าเจ้าของพิมพ์ `somchai@gmial.com` (typosquat ที่มีคนถือจริง) → คนคนนั้นได้สิทธิ์เข้าร้านจริงตั้งแต่ล็อกอินครั้งแรก

**วันนี้ช่องนี้เงียบ พอ Q5 เพิ่มจดหมายแจ้ง เราเดินไปบอกเขาเอง** จดหมายไม่ได้สร้างช่องโหว่ — แถว membership ต่างหากที่สร้าง — แต่มัน**ประกาศ**ช่องโหว่ให้คนที่อยู่ผิดฝั่งพอดี

**ไม่เพิ่มเครื่องจักรอะไรเลย:**

1. จดหมาย**บอกชื่อร้านและบทบาท** ให้คนอ่านตัดสินได้ว่าใช่เขาไหม
2. จดหมายจบด้วย *"ถ้าคุณไม่รู้จักร้านนี้ ไม่ต้องทำอะไร"* — คนที่ได้รับผิดคือคนที่รู้ดีที่สุดว่ามันผิด
3. **ไม่มีลิงก์ที่ล็อกอินได้** (กฎข้อ 1 ของ Q5) การเข้าถึงยังต้องอาศัยการลงมือของเขาเอง ไม่ใช่การกดครั้งเดียว
4. **คนจับผิดคือเจ้าของ ผ่านของที่ Part 29 ทำไว้แล้ว** — `neverSignedIn` บนหน้า "คนในร้าน" คือที่ที่ที่อยู่ผิดจะนั่งค้างพร้อมป้าย "ยังไม่เคยเข้าใช้งาน"

**ปฏิเสธ: ขั้นยืนยันที่อยู่ก่อนบันทึก** — คนกดยืนยันโดยไม่อ่าน มันย้ายความรับผิดชอบมากกว่าลดความเสี่ยง · **ปฏิเสธ: ขั้นตอน "ยอมรับคำเชิญ"** — อันนี้แก้ปัญหาได้จริง แต่คือการกลับคำ ADR 0029 Q2 ทั้งข้อ ซึ่งใหญ่กว่า Part นี้มาก ถ้าจะทำต้องเป็น Part ของมันเอง

### Q9 — ส่งไม่สำเร็จต้องล้มให้เห็น

ทางนี้**ยังไม่เคยมีใครเดินเลยสักครั้ง** เพราะ dev แค่ log และ production โยนตั้งแต่ต้นทาง พอเปิดสวิตช์มันจะเดินได้จริงเป็นครั้งแรก

1. **ห้ามกลืน error แล้วโชว์ "เช็คอีเมลของคุณ"** นั่นคือหน้าจอที่โกหก คนจะไปนั่งรอเมลที่ไม่มีวันมาแล้วสรุปว่า Mise พัง — กฎ C10/W4 ของโปรเจกต์ในรูปของหน้าจอ: สิ่งที่ปิดที่มาของตัวเองคือสิ่งที่ถูกเชื่อเกินกว่าที่สมควร
2. **เพิ่ม `pages.error`** (ข้อเท็จจริง 8 — ไม่มีวันนี้) ชี้ไป `/login?error=…` แล้วหน้า login พูดเป็นไทย ไม่ต้องสร้าง route ใหม่ เพราะ `/login` รับ `searchParams` อยู่แล้ว
3. **log อังกฤษพร้อมสาเหตุ SMTP, แสดงไทยแบบไม่มีรายละเอียด** ตาม convention ของ CLAUDE.md และไม่โยนรหัส SMTP ใส่หน้าผู้ใช้
4. **ฝั่งคำเชิญใช้กฎคนละข้อโดยเจตนา** — ที่นั่นส่งล้มไม่ทำให้คำเชิญล้ม (Q5 เส้นที่ 3) เพราะแถวถูกเขียนแล้วและถูกต้อง ที่นี่ส่งล้มแปลว่า**ไม่มีอะไรเกิดขึ้นเลย** จึงต้องบอกให้ลองใหม่

**ส่ง multipart ทั้ง `text` และ `html`** — nodemailer ทำได้ในตัว ไม่ต้องมี template engine ไม่ต้องมี dependency ใหม่ ได้ deliverability ของ plain text และหน้าตาที่ดูเป็นของจริงสำหรับเจ้าของร้านพร้อมกัน HTML เขียนมือสั้นที่สุด: หัวเรื่อง + ปุ่ม + **URL เต็มเป็นข้อความให้ copy ได้** เผื่อปุ่มกดไม่ติดในแอปเมลบางตัว

## Consequences

1. **Part 20b ยังบล็อกอยู่ และตอนนี้บล็อกอยู่ลำพัง** ADR 0030 Consequence 5 มัดสองอย่างไว้ด้วยกัน Q1 แก้มัดนั้น — ประโยค *"blocked on choosing an inbound-mail vendor"* ใน CLAUDE.md และ `sprint-progress.md` ต้องถูกเขียนใหม่ให้พูดถึงขาเข้าอย่างเดียว

2. **คำเชิญของ Part 29 ยังใช้จริงไม่ได้จนถึง C** Part นี้ทำให้จดหมายส่งออกไปได้ แต่ลิงก์ข้างในยังชี้ `localhost` จนกว่าจะมี deployment — **อย่าอ่าน ADR นี้ว่า "คำเชิญใช้ได้แล้ว"**

3. **เงื่อนไขที่จะบังคับให้ย้ายจาก SMTP ไป HTTP SDK — เขียนไว้เป็นของที่ต้องเฝ้า ไม่ใช่ความเสี่ยงลอย ๆ:** (1) host ที่เลือกกั๊ก port ขาออก 25/465/587 · (2) handshake บน cold start ทำให้กด "ส่งลิงก์" แล้วรู้สึกค้าง จนคนกดซ้ำ · (3) ต้องการ webhook bounce/complaint ผูกกับ message id รายฉบับ ซึ่ง SMTP ให้แค่ queue id · (4) ต้องใช้ feature ที่ vendor เปิดเฉพาะทาง HTTP · ข้อ 1–2 มีโอกาสเกิดจริง ราคาการย้าย = ไฟล์เดียว ~20 บรรทัด + สลับ dependency

4. **คำเชิญที่พิมพ์ผิดให้สิทธิ์จริงตั้งแต่ล็อกอินครั้งแรก** นี่คือคุณสมบัติของ ADR 0029 ที่ยอมรับไว้แล้ว **ไม่ใช่บั๊กที่เพิ่งเกิด** — Part นี้ทำให้มันถูกค้นพบง่ายขึ้นเท่านั้น ถ้าวันหนึ่งมีร้านจริงเจอเข้า ทางแก้ที่ถูกต้องคือ Part ที่กลับคำ ADR 0029 Q2 ไม่ใช่การถอดจดหมายแจ้งออก

5. **ชั้น 2 ของ Q6 เป็นหนี้ที่มีกำหนดชำระ** — **ก่อน verify โดเมน ไม่ใช่ก่อน deploy** เป็นหนี้ก้อนแรกของโปรเจกต์ที่กำหนดชำระผูกกับเหตุการณ์ที่ไม่ใช่ Part

6. **`nodemailer` เลิกเป็น dependency ที่ไม่มีใครใช้** หลังจากอยู่ใน `package.json` มาตั้งแต่ Sprint 0 — และ `EMAIL_FROM` ใน `.env` ได้ผู้อ่านคนแรก

7. **ชุดเทสต์ยังยิงเมลจริงไม่ได้** (ข้อเท็จจริง 9) และตาราง Q7 รักษาสมบัติข้อนั้นไว้: ไม่มีเทสต์ไหนตั้ง SMTP config เพราะฉะนั้นทุกเทสต์อยู่ในคอลัมน์ขวา

🛑 **ต้องมี Kong ก่อนเริ่ม:** สมัครบัญชี Resend และเอา SMTP credential ลง `.env` — เป็น `.env` edit ตาม CLAUDE.md · **ไม่มี migration ไม่มี dependency ใหม่ทั้ง Part**
