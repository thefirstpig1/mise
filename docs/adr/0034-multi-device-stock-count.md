# ADR 0034 — นับสต๊อกหลายเครื่องพร้อมกัน: ใบเดียว เจ้าภาพคนเดียว ส่วนนับมีเจ้าของ

**Status:** accepted · **Date:** 2026-09-28 · **Grill:** Q1–Q7 (Kong, 2026-09-28)
**Part:** Sprint 7 Part 36 · **แก้** ADR 0015 Q2 (ใครนับ และการทับตัวเลข) และ ADR 0029 (เพิ่มบทบาทที่แปด) · **มี migration** (ตารางใหม่หนึ่งตาราง)

## Context

Kong ลองหน้านับสต๊อกแล้วเจอสี่เรื่อง และข้อเท็จจริงที่ตรวจจากโค้ดและวัดจริงวันเดียวกัน:

1. **ช่องใส่ตัวเลขถูกบีบจนแทบมองไม่เห็น** — dropdown หน่วยมี class `"input w-full w-40"` สองความกว้างชนกัน `w-full` ชนะ ช่องตัวเลขเป็น `flex-1` จึงหดเหลือเกือบศูนย์
2. **บันทึกทีละรายการแล้วทั้งหน้าโหลดใหม่** — ทุกครั้งที่บันทึก `revalidatePath` ทำให้ทั้งหน้า render ใหม่ วัดได้ **1.2–2.2 วินาทีต่อครั้ง** (ใบว่าง ~1.1 s · 26 บรรทัด ~1.5–2.2 s) เพราะหน้านั้นอ่านสินค้าทุกตัว + **replay FIFO ของทุกสินค้าที่นับแล้ว** + นับรายการที่ยังไม่นับใหม่ ทั้งที่ action ส่งข้อมูลใบกลับมาอยู่แล้ว · **ยิ่งนับมาก ยิ่งช้า** — ตรงข้ามกับที่งานนับต้องการ
3. **ช่อง "ผู้นับ" เป็นข้อความอิสระ** (`counted_by_name`) — พิมพ์ชื่อใครก็ได้ Kong: *"ถึงจะให้คนอื่นเดินนับแต่ตัวเองก็ต้องเป็นคนรับผิดชอบตรวจสอบ ไม่งั้นมันจะมีการใส่ชื่อคนอื่น นับผิดๆไปได้"*
4. **ช่องหมายเหตุว่างเปล่า** — พนักงานไม่รู้ว่าควรเขียนอะไร และหมายเหตุคือสิ่งเดียวที่ทำให้ตรวจย้อนหลังได้

แล้ว Kong ออกแบบ flow ใหม่ทั้งหมด: *ครัวนับพร้อมกันห้าเครื่อง* — เจ้าภาพเปิดใบ คนอื่นเข้าใบเดียวกัน แต่ละบรรทัดมีปุ่มยืนยันท้ายบรรทัด พอยืนยันแล้วบรรทัดนั้น**เป็นสีเขียวบนทุกเครื่องพร้อมชื่อคนนับ** คนเดินจะรู้ทันทีว่าอะไรนับแล้ว

ข้อเท็จจริงที่ ADR 0015 Q2 ตั้งอยู่บนมัน **ไม่จริงแล้ว**: *"In a Thai SME the owner holds the only login"* — ตั้งแต่ Part 29 (ADR 0029) ร้านเชิญพนักงานเข้ามามีแอคเคาท์ของตัวเองได้

## Decision

### Q1 — ผู้นับ = แอคเคาท์ที่กดยืนยัน เท่านั้น

เลิกเขียน `counted_by_name` · คอลัมน์ยังอยู่ (nullable) เพื่อให้ใบเก่าแสดงผลได้ และค่าเดิมถูกคัดไปต่อท้ายหมายเหตุของส่วนนับตอน backfill ไม่หาย · **ถ้าอยากให้พนักงานนับ ให้เชิญเขาเข้าร้าน** — นั่นคือสิ่งที่ Part 29 สร้างมาเพื่อ

### Q2 — บรรทัดหนึ่ง = หลายส่วนนับ แต่ละส่วนมีเจ้าของ (ไม่ทับอีกต่อไป)

ADR 0015 Q2 ให้การนับซ้ำ **ทับ** ของเดิม ("the draft is a working sheet") ซึ่งถูกเมื่อคนนับคือคนเดียว · เมื่อหลายเครื่องนับพร้อมกัน การทับคือ**ตัวเลขของอีกคนหายเงียบ ๆ** และของชิ้นเดียวกันอยู่หลายที่จริง (หมูสับในห้องเย็น + ตู้หน้าไลน์)

Kong เลือก **รวมเพิ่ม + บันทึกชื่อทุกคน** → ตารางใหม่ `stock_count_contribution` = "ส่วนนับหนึ่งครั้งของหนึ่งคน" (คนนับ · เวลา · หมายเหตุ) และ `stock_count_entry` ชี้ไปที่ส่วนนับของมัน · หนึ่งส่วนมีหลายหน่วยได้ ("2 กระสอบ + 3 kg") แต่มีคน/เวลา/หมายเหตุชุดเดียว — จึงเป็นตาราง ไม่ใช่คอลัมน์ซ้ำบนทุก entry

`stock_count_item.qty_counted` **ยังเป็นยอดรวม** และยังเป็นสิ่งเดียวที่การปิดใบอ่าน → การปิดใบ ledger และ `fifo-replay.ts` **ไม่เปลี่ยนเลย**

### Q3 — บันทึกมีสามแบบ และไม่มีแบบไหนแตะส่วนของคนอื่น

| แบบ | ใช้เมื่อ | ถ้ามีคนนับไปก่อนแล้ว |
|---|---|---|
| **ยืนยัน** (บรรทัดใหม่) | เห็นว่ายังไม่มีใครนับ | **ปฏิเสธ** พร้อมบอก "คุณเอนับไปแล้ว 4.5 กก. เมื่อ 10:32" — ไม่ทับ |
| **นับเพิ่มจากอีกที่** | ของอยู่หลายที่ | เพิ่มเป็นส่วนใหม่ของฉัน ยอดรวม |
| **แก้ของฉัน** | ใส่ผิดเอง | แก้ได้เฉพาะส่วนที่ฉันนับ |

ส่วนของคนอื่นแก้ไม่ได้ — ความรับผิดชอบเป็นรายคน (Q1) · ทั้งบรรทัดยังเอาออกได้ด้วยปุ่มเดิม (แต่ละส่วนก็ลบได้ทีละส่วนโดยเจ้าของ)

**ทำไมต้องเช็คที่เซิร์ฟเวอร์ ไม่ใช่แค่สีเขียว** — สีเขียวมาถึงเครื่องอื่นช้าได้ถึงรอบ polling หนึ่งรอบ สองคนกดยืนยันของชิ้นเดียวกันห่างกันไม่ถึงนั้น เครื่องที่สองยังไม่เขียว · สีเขียวคือ*ความสะดวก* การเช็คตอนยืนยันคือ*การรับประกัน*

ทุกการบันทึก**ล็อกแถวใบนับก่อน** (`SELECT … FOR UPDATE`) — ห้าเครื่องกดพร้อมกันจึงเรียงคิวกันทำงานเป็นมิลลิวินาที แทนที่จะชน partial unique `stock_count_item_product_unique` แล้วได้ error ดิบ

### Q4 — `qty_expected` ถ่ายใหม่ทุกครั้งที่มีส่วนนับเพิ่ม

ADR 0015 Q3 ถ่าย snapshot ตอนบันทึก ไม่ใช่ตอนปิดใบ เหตุผลนั้นยังอยู่: ของที่รับเข้าระหว่างนับกับปิดใบต้องไม่อ่านเป็นส่วนขาด · ส่วนนับที่มาทีหลังจึงถ่าย snapshot ใหม่ของทั้งบรรทัด และ `counted_at` ของบรรทัด = เวลาของส่วนล่าสุด (เวลาที่ส่วนต่างเกิด — Q8 เดิม)

### Q5 — เจ้าภาพ และใครปิดใบได้

ใบนับมีเจ้าภาพเสมอ = คนเปิดใบ (`started_by`) · **สาขาละใบเปิดได้ใบเดียว** (มีอยู่แล้ว — `stock_count_open_unique`) และการกดเปิดใบในสาขาที่มีใบค้าง**พาเข้าใบนั้นเลย** แทนการขึ้น error

ปิดใบและยกเลิกใบได้: **เจ้าภาพ** + ผู้ถือความสามารถ `count:close` = เจ้าของร้าน · ผู้ดูแลส่วนกลาง · ผู้จัดการ · หัวหน้าแผนก (Kong) · เจ้าภาพลาป่วยหรือกลับบ้านแล้ว ใบต้องไม่ค้างทั้งสาขา จึงต้องมีคนอื่นปิดแทนได้

ตรวจใน logic ไม่ใช่แค่ซ่อนปุ่ม — action ส่ง `canCloseAny = hasCapability(role, "count:close")` และ logic ปฏิเสธ `NotCountHostError` เมื่อไม่มีสิทธิ์และไม่ใช่เจ้าภาพ

### Q6 — บทบาทที่แปด `dept_head` หัวหน้าแผนก

หัวหน้าครัว หัวหน้าบาร์ หัวหน้าเบเกอรี่ (Kong) = ความสามารถทั้งหมดของพนักงานครัว + `count:close` · ไม่เห็นเงินเหมือนพนักงานครัว · เป็นแค่การแก้โค้ด เพราะ `role` เป็น String (ADR 0029) · subset containment ยังถือ: ผู้จัดการมี `count:close` จึงเชิญหัวหน้าแผนกได้

ไม่ผูกหัวหน้าแผนกกับแผนกใดแผนกหนึ่งในรอบนี้ — ใบนับเป็นของทั้งสาขา ไม่มีแผนก (ADR 0015) · หัวหน้าแผนกจะทำอะไรเพิ่ม (เช่น อนุมัติของเสีย) เติมที่บทบาทนี้ทีหลังได้

### Q7 — เครื่องอื่นเห็นสีเขียวด้วยการถามทุก 5 วินาที ไม่ใช่ real-time

แต่ละเครื่องที่เปิดใบอยู่ถามเซิร์ฟเวอร์ทุก 5 วินาที **เฉพาะตอนหน้าจอเปิดอยู่** และถามทันทีเมื่อกลับมาที่แท็บ · คำถามนี้อ่านแค่บรรทัดกับส่วนนับ **ไม่มี FIFO** · real-time จริงต้องมี vendor ใหม่ (websocket) ซึ่งไม่คุ้มกับงานที่ห่าง 5 วินาทีแล้วไม่มีใครสังเกต และ Q3 ปิดช่องที่ความหน่วงนั้นเปิดไว้แล้ว

และการบันทึกเลิก revalidate หน้าใบนับ (ตัวการของ 1–2 วินาทีต่อครั้ง) — client อัปเดตบรรทัดจากคำตอบของ action เอง · revalidate เฉพาะตอนปิด/ยกเลิกใบ ซึ่งเปลี่ยนสต๊อกจริง

## Consequences

1. **ตารางใหม่หนึ่งตาราง** `stock_count_contribution` — มี `tenant_id` จึงต้องมี policy ใน `enable_rls.sql` + FORCE ใน `enforce_rls.sql` และอยู่ใน `TENANT_SCOPED_DELETE_ORDER` (เทสต์ sweep-coverage แดงถ้าลืม)
2. **ใบเก่าไม่เสียอะไร** — backfill สร้างหนึ่งส่วนนับต่อบรรทัดเก่า จากคนนับ/เวลา/หมายเหตุของบรรทัด และ `counted_by_name` เก่าไปต่อท้ายหมายเหตุ
3. **ใบนับแบบปิดตา (blind) ยังเหมือนเดิม** — เครื่องอื่นเห็นว่านับแล้วโดยใคร และเห็นจำนวนที่นับได้ แต่ไม่เห็น "ระบบว่ามี"
4. **ADR 0015 Q2 ประโยค "overwriting the previous entry" ไม่จริงแล้ว** — ร่างยังเป็นกระดาษทำงาน แต่คนหนึ่งลบรอยของอีกคนไม่ได้
5. เพิ่มเวลาปิดใบเล็กน้อยไม่ได้ — การปิดยังอ่าน `qty_counted`/`qty_expected` ของบรรทัดเหมือนเดิม
