# ADR 0043 — ผู้ดูแลระบบ (platform admin / super account)

**Status:** accepted · **Date:** 2026-10-30 · **Decided by:** Kong (chat, 2026-10-30: "เอาตามแผน ทำให้เลย")
**Migration:** `20261030090000_platform_audit_log` (1 ตารางใหม่ ไม่ผูกร้าน)
**แก้ต่อจาก:** ADR 0030 (ประตูข้าม RLS มีบานเดียว) · billing step 1 (`scripts/plan.mjs`, 2026-10-29)

## Context
Kong (30 ต.ค.): *"ทำให้ account ผมเป็น super account แล้วสามารถจัดการแอพ จัดการผู้ใช้ได้เองก็ยิ่งดี เพราะหลังจากนี้งานขายจะเป็นงานของผมแล้ว แล้วผมจะเป็นคนที่ approve ได้เอง ... แล้วยิ่งจำกัดการให้สิทธิฟรีแต่ละคนมันไม่เท่ากันด้วย"*

ก่อนหน้านี้ (29 ต.ค.) แพ็กเกจของร้านตั้งด้วยคำสั่งบนเครื่องโปรดักชัน เพราะหน้าที่เห็นทุกร้านคือ **ประตูข้าม RLS บานที่สอง** ซึ่ง ADR 0030 ตั้งใจให้มีบานเดียว Kong ตัดสินว่าความสะดวกของงานขายคุ้มกับบานที่สอง ถ้าคุมบานนั้นให้แน่น

## Decision

**Q1 · ใครเป็นผู้ดูแลระบบ: รายชื่ออีเมลใน secret `PLATFORM_ADMIN_EMAILS`** (คั่นด้วยจุลภาค ไม่สนตัวพิมพ์) — **ไม่ใช่คอลัมน์ในฐานข้อมูลและไม่ใช่ปุ่มในแอป** เพราะอะไรก็ตามที่แอปเขียนได้ คนที่ยึดบัญชีในแอปได้ก็เขียนได้ · การเพิ่มผู้ดูแลต้องแก้ secret บน Fly = ต้องมีสิทธิ์ในบัญชี Fly ซึ่งเป็นอีกชั้นหนึ่ง · ไม่มีชื่อในรายการ = หน้า `/platform` ตอบ **404** ไม่ใช่ "ไม่มีสิทธิ์" (ไม่ยืนยันว่าหน้านี้มีอยู่)

**Q2 · ประตูบานที่สองอยู่ไฟล์เดียว: `src/server/platform.ts`** — เข้า `ALLOWED` ของ `tests/rls-bypass-guard.test.ts` พร้อมเหตุผล · **ทุกฟังก์ชันในไฟล์รับ `PlatformActor` ที่ได้จาก `requirePlatformAdmin()` เท่านั้น** (type ที่สร้างได้ทางเดียว) จึงเรียกจากหน้าร้านโดยไม่ผ่านการตรวจไม่ได้

**Q3 · ทำอะไรได้ (รอบแรก)**
- **ร้านทั้งหมด:** ชื่อ · วันสมัคร · อีเมลเจ้าของ · จำนวนสาขา/คน · ใช้งานล่าสุด (สต๊อกหรือบิลล่าสุด) · แพ็กเกจ · ใช้ฟรีถึง
- **แก้แพ็กเกจรายร้าน** (แทน `scripts/plan.mjs` ซึ่งยังอยู่เป็นทางสำรอง) — ฟรีกี่เดือนก็ได้ ไม่ต้องเท่ากัน
- **ดูคนในร้าน** (อ่านอย่างเดียว — เจ้าของร้านจัดการคนในร้านเองได้อยู่แล้ว ADR 0029)
- **ค้นหาผู้ใช้จากอีเมล:** อยู่ร้านไหน บทบาทอะไร
- *(ไม่ทำรอบนี้: ระงับร้าน — ต้องตัดสินก่อนว่าร้านที่เลยกำหนดจะเป็นอย่างไร · เปลี่ยนอีเมลเจ้าของร้านแทนลูกค้า)*

**Q4 · บันทึกทุกการแก้ไข** ลง `platform_audit_log`: ใคร (อีเมล ณ ตอนนั้น) · ทำอะไร · ร้านไหน (id + ชื่อ ณ ตอนนั้น) · ก่อน/หลัง (JSON) · เมื่อไร · **ไม่ผูก FK กับร้าน** — บันทึกต้องอยู่ต่อแม้ร้านถูกลบ · ตาราง **เปิด RLS + FORCE แต่ไม่มี policy** = role `mise_app` ของแอปแตะไม่ได้เลย มีแต่ประตูบานที่สองที่อ่าน/เขียนได้ · เขียนในทรานแซกชันเดียวกับการแก้ ไม่มีการแก้ที่ไม่มีบันทึก

## Consequences
1. `PLATFORM_ADMIN_EMAILS` ต้องตั้งบน Fly ด้วยมือ Kong (classifier ไม่ให้ agent เขียน secret) — ยังไม่ตั้ง = ไม่มีใครเข้า `/platform` ได้ ซึ่งเป็นค่าที่ปลอดภัย
2. ประตูข้าม RLS มีสองบานแล้ว — allowlist ต้องหยุดที่สอง บานที่สามต้องมี ADR ของตัวเอง
3. อีเมลผู้ดูแลอยู่ใน secret ไม่ใช่ในโค้ด จึงไม่หลุดไปกับ repo
