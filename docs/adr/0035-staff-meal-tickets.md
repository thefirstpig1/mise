# ADR 0035 — ตั๋วเบิกมื้อพนักงาน: คนกินขอเอง หัวหน้าอนุมัติ ร้านเลือกว่าใครตัดสต๊อก

**Status:** accepted · **Date:** 2026-09-28 · **Grill:** Q1–Q7 (Kong, 2026-09-28)
**Part:** Sprint 7 Part 37 · **แก้** ADR 0028 Q3 (ระบบไม่รู้จักคน → roster ผูกแอคเคาท์ได้) · ต่อจาก ADR 0034 Q1 (ความรับผิดชอบผูกแอคเคาท์) · **มี migration**

## Context

หน้ามื้อพนักงานให้คนบันทึก **เลือกชื่อพนักงานจาก dropdown** ว่าใครกิน — Kong: *"บัญชีที่กดเบิกก็ต้องเป็นของพนักงานเองไง จะได้ไม่ต้องเป็น drop down เดี๋ยวมีคนกดชื่อคนอื่น"* หลักเดียวกับที่ ADR 0034 ใช้กับใบนับ: ตัวเลขที่ใครคนหนึ่งต้องรับผิดชอบ ต้องผูกกับแอคเคาท์ของคนนั้น ไม่ใช่กับชื่อที่ใครก็พิมพ์ได้

ADR 0028 Q3 ตั้งอยู่บนข้อเท็จจริงว่า *"ระบบไม่เคยรู้จักคน"* จึงสร้าง `staff_member` เป็นรายชื่อพิมพ์มือ — ตั้งแต่ Part 29 ร้านเชิญพนักงานมีแอคเคาท์ได้แล้ว ข้อเท็จจริงนั้นจึงจริงแค่ครึ่งเดียว: **พนักงานประจำมีแอคเคาท์ได้ พาร์ทไทม์ส่วนใหญ่ไม่มี** (Kong)

อีกเรื่องที่ ADR 0028 Q6 แก้ได้แค่เตือน: ร้านที่คีย์มื้อพนักงานเข้า POS เป็นยอดขายราคา ฿0 อยู่แล้ว POS import จะตัดสต๊อกผ่าน Part 22 และการบันทึกซ้ำที่นี่ **ตัดสองรอบ** — ระบบเตือนได้แต่แยกไม่ออก

## Decision

### Q1 — พนักงานขอเบิกด้วยแอคเคาท์ตัวเอง (เมนูในร้าน)
พนักงานที่มีแอคเคาท์กด "ขอเบิก" → ผู้กินคือตัวเขาเองเสมอ ไม่มีช่องเลือกคน · roster ผูกกับแอคเคาท์ผ่าน `staff_member.user_id` (คนหนึ่งแถวเดียวต่อร้าน) และ **ระบบสร้างแถวให้เองครั้งแรกที่ขอ** (ชื่อจากแอคเคาท์ สาขาบ้าน = สาขาแรกที่แอคเคาท์เข้าถึง) — โควตาเดิมที่ผูกกับ `staff_member` ใช้ต่อได้ทั้งหมด

### Q2 — ไม่มีแอคเคาท์ → หัวหน้าบันทึกแทน ติดป้ายเสมอ
พาร์ทไทม์ = แถว roster ที่ `user_id` ว่าง · ผู้ถือ `staffmeal:approve` เลือกจาก roster กลุ่มนี้และบันทึก **แทน** ได้ — เอกสารมี `on_behalf = true` และหน้าจอเขียน **"บันทึกแทนโดย [แอคเคาท์]"** ทุกครั้ง · การบันทึกแทนคือการอนุมัติไปในตัว (คนที่มีสิทธิ์อนุมัติเป็นคนบันทึก) · **พนักงานธรรมดาเลือกชื่อคนอื่นไม่ได้เลย** และบันทึกแทนคนที่มีแอคเคาท์ไม่ได้ (คนนั้นต้องขอเอง)

### Q3 — ตั๋ว: รออนุมัติ → อนุมัติ / ไม่อนุมัติ
เอกสารมี `status` + `ticket_no` (`{BRANCH}-SM-####` ต่อสาขา, counter lock เดียวกับเอกสารอื่น) + เวลาที่ขอจริง · พนักงานเอาตั๋วบนจอไปโชว์ · **ตั๋วที่รออนุมัติไม่มี item และไม่แตะ ledger** · อนุมัติ → explode สูตรของ **วันที่บนตั๋ว** แล้วเขียน items + `CONSUMPTION` (ถ้าร้านให้ระบบตัด — Q4) · ไม่อนุมัติ → สต๊อกไม่ขยับ ต้องใส่เหตุผล · ตั๋วค้างข้ามวันไม่หมดอายุเอง ยังอยู่ในคิว เพราะ "ลืมกด" ไม่ใช่ "ไม่อนุมัติ"
ตอนขอระบบ **ตรวจล่วงหน้าว่าสูตร explode ได้** (เมื่อระบบต้องตัด) จะได้ไม่ไปพังที่มือผู้อนุมัติ และ **แช่แข็งราคาตอนขอ** (rule S2 เดิม)

### Q4 — ใครตัดสต๊อก = ค่าตั้งของร้าน
`tenant.staff_meal_stock_source`: **`SYSTEM`** (ค่าเริ่มต้น = พฤติกรรมเดิม — ระบบตัดตอนอนุมัติ) / **`POS`** (ร้านคีย์มื้อพนักงานเข้า POS อยู่แล้ว — POS import ตัด ระบบบันทึกตั๋วเพื่อโควตาและหลักฐานเท่านั้น) · ค่าที่ใช้ **แช่แข็งลงเอกสารตอนอนุมัติ** (`stock_posted`) เหมือน `cancelled_sale_policy` — เปลี่ยนค่าตั้งวันนี้ต้องไม่เปลี่ยนความหมายของตั๋วเมื่อวาน · หม้อใหญ่ตัดเสมอ (POS ไม่มีรายการหม้อใหญ่) · ร้านแบบต่าง ๆ ต่างกันจริง จึงเป็นค่าตั้ง ไม่ใช่ค่าเดา

### Q5 — ผู้อนุมัติ = `staffmeal:approve`
เจ้าของ · ผู้ดูแลส่วนกลาง · ผู้จัดการ · หัวหน้าแผนก · **อนุมัติตั๋วที่ตัวเองเป็นผู้กินไม่ได้** (ตรวจใน logic) · ผู้อนุมัติเห็นโควตาของคนนั้นวันนี้ก่อนกด (ใช้ไป/เหลือ) — โควตายังเตือนอย่างเดียว ไม่ห้าม (ADR 0028 เดิม)

### Q6 — วันที่และสาขาล็อก
วันที่ = วันนี้ (Bangkok) ยกเว้นผู้ถือ `settings:write` (เจ้าของ/ผู้ดูแลส่วนกลาง) ที่ย้อนหลังได้ตามกรอบเดิม · สาขา = ล็อกเมื่อแอคเคาท์เข้าถึงสาขาเดียว · เข้าถึงหลายสาขา (เจ้าของ ผู้บริหาร area manager) เลือกได้ (Kong)

### Q7 — หม้อใหญ่คงเดิม
ทำกินเองจากของในร้าน: คนทำบันทึกด้วยแอคเคาท์ตัวเอง ตัดทันที ไม่มีตั๋ว ไม่มีอนุมัติ (Kong) · ช่อง "ใครกิน" ของหม้อใหญ่เป็นของผู้ถือ `staffmeal:approve` เท่านั้น

## Consequences
1. โควตานับเฉพาะตั๋ว `APPROVED` · ตั๋วที่รอแสดงแยกให้ผู้อนุมัติเห็น
2. แถวเก่าทั้งหมด backfill = อนุมัติแล้ว ระบบตัดแล้ว (`stock_posted = true`) ผู้อนุมัติ = คนบันทึก — ตรงกับที่มันเกิดขึ้นจริง
3. `voidStaffMealLogic` ใช้ต่อกับตั๋วที่อนุมัติแล้ว · ตั๋วที่ `stock_posted = false` ยกเลิกได้โดยไม่มีอะไรต้องคืน
4. คำเตือน "ยอดขายราคา ฿0 อาจตัดซ้ำ" (ADR 0028 Q6) ยังอยู่เฉพาะร้าน `SYSTEM` — ร้าน `POS` เลือกแล้วว่า POS ตัด
5. ไม่มีการแจ้งเตือน push/LINE ในรอบนี้ ผู้อนุมัติเห็นคิวที่หน้าและแดชบอร์ด
